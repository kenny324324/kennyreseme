# Kenny Yu 台灣與外商求職市場研究報告

查詢日期：2026-05-21  
研究對象：Kenny Yu（余亮廷）  
目前定位：行動產品工程師 / iOS 與 Flutter App 開發者，約 2.5 年公司與個人產品經驗

## 1. 先講結論

你已明確不打算用 .NET MAUI 或純 UI/UX 方向投職，所以本報告把它們視為「過去經驗可轉譯的背景能力」，不列入投遞主線。你現在最有機會談到好條件的定位是：

1. **Mobile Product Engineer / iOS Engineer**
   - 核心賣點：SwiftUI、App Store 上架、Firebase/CloudKit/SwiftData/StoreKit、地圖、推播、AI 整合、能自己把 App 從 0 到上架做完。
   - 最適合投：PicCollage、Gogoro、LINE Bank、Yahoo、17LIVE、Gogolook、SHOPLINE、Binance。

2. **Flutter / Cross-platform Mobile Engineer**
   - 核心賣點：Flutter + Firebase + RevenueCat + 多語系 + 上架審核經驗。
   - 最適合投：Jubo、TutorABC Shop 類、電商/教育/生活服務 App、新創與中型 SaaS。

3. **Product-minded Mobile Engineer / Technical PM**
   - 核心賣點：你不是只寫功能，還能整理需求、接客戶回饋、做 Notion 文件、驗收、PM 協作。
   - 最適合投：XREX Technical PM、軟體產品經理、行動產品 Product Owner、B2B SaaS 產品團隊。

## 2. 你的市場定位

### 你的強項

- **真實商業 App 經驗**：跳蛙公車 2.0、TUAN AI 助理、島嶼生吐司 POS，涵蓋購票、地圖、推播、第三方登入、語音、條碼掃描、API 串接。
- **完整個人產品證明**：Pickup、Mish、FindToilets、Mino、spo.stats 已有多個 App Store 上架作品。
- **產品感比一般 junior/mid 工程師強**：你能處理 UI/UX、需求拆解、測試回饋、文件與上架，不只是接 ticket。
- **App Store / IAP / 訂閱經驗稀有**：StoreKit 2、RevenueCat、審核退件修正，這在面試非常好講。
- **AI 不是只寫在履歷上的 buzzword**：Pickup 有 AI 截圖辨識，SoulFeed/TUAN 有 AI 互動，PicCollage、Yahoo、Gogolook 這類公司現在也明確要求 AI 工具或 AI product sense。
- **AI-native / Agent-assisted 開發經驗**：你的開發方式本來就是在 AI 盛行後開始形成，熟悉用 agent 把想法、介面、功能與上架流程快速推進。這可以成為差異化，但必須包裝成「我會用 AI 提升產品交付速度，並能驗證與負責結果」，不能只說 vibe coding。
- **英文可用**：TOEIC 835，可以往外商和跨國團隊投，但要補強英文面試與英文技術敘述。

### 主要風險

- **商業 iOS 年資不足**：你有很多 SwiftUI 個人作品，但公司正式職務不是 native iOS；外商 iOS 職缺常要求 3-5 年 production iOS、UIKit、Objective-C、大型 codebase。
- **SwiftUI 強，但 UIKit/Objective-C/測試/CI/CD 需要補強**：多數高薪 iOS 職缺仍看 UIKit、legacy code、unit/UI tests、Fastlane、CI/CD。
- **語法與底層熟悉度不足會被面試放大**：AI 輔助開發已經是趨勢，但公司仍會確認你能不能讀懂 agent 產出的 code、判斷好壞、debug、改 bug、加測試、解釋 trade-off。真正的風險不是「用了 AI」，而是「無法對 AI 產出的結果負責」。
- **Flutter 是加分，不是目前最強主軸**：Mish 很適合證明跨平台，但若投 senior Flutter，商業 Flutter 年資會被挑戰。
- **過去公司技術棧需要重新敘事**：商業案不要主打技術名稱，而要轉成「商業 App 交付、API、推播、地圖、登入、語音、硬體整合、跨部門協作」這些可被 iOS / Flutter 職缺理解的成果。

## 7. 履歷與作品集調整建議

### 履歷主標題建議

不要寫得太像純 UI/UX，也不要把過去公司技術棧放在主標題。建議改成：

> Mobile Product Engineer | iOS / Flutter | Product-minded App Developer

中文可寫：

> 行動產品工程師｜iOS / Flutter｜具產品設計感與 App 上架經驗

如果要把 AI 開發方式放進標題，可以用比較職場可接受的說法：

> AI-native Mobile Product Engineer | iOS / Flutter | Agent-assisted App Development

中文可寫：

> AI 原生行動產品工程師｜iOS / Flutter｜擅長用 Agent 加速 App 交付

### 最前面摘要建議

用 4 點打中外商與產品公司的需求：

- 2.5 年商業 App 與專案協作經驗，參與交通購票、AI 助理、POS 內部系統。
- 獨立設計、開發並上架多款 iOS/Flutter App，涵蓋 Firebase、CloudKit、SwiftData、StoreKit 2、RevenueCat、WidgetKit、MapKit。
- 熟悉從 App 介面流程、API 串接、推播、第三方登入、地圖、訂閱到 App Store 審核的完整流程。
- 能與 PM、設計、後端、客戶協作，將模糊需求整理成可開發、可驗收的產品交付。
- 熟悉以 AI agent 輔助開發，能快速完成 prototype、功能實作、除錯方向探索與文件整理，並透過測試、人工 review 與實機驗證確認品質。

### AI / Agent-assisted 開發要怎麼講

不要把「Vibe Coding」當成主標籤，因為有些面試官會把它理解成「不懂 code，只靠 AI 猜」。建議改成：

- **可放履歷的說法**：AI-assisted development、Agent-assisted prototyping、AI-native product development workflow。
- **面試時的說法**：我用 agent 提升探索與實作速度，但我會負責需求拆解、架構選擇、實機測試、錯誤處理、上架驗證與最後品質。
- **不要說的方式**：我其實不太懂語法，都是 AI 幫我寫。這句會讓公司擔心你無法維護 production code。
- **可以誠實但更好的說法**：我的開發流程是 AI-native，所以我不會把價值放在死背語法，而是放在拆問題、讀懂產出、驗證行為、debug、整合服務和交付產品。接下來三個月我會補強 UIKit、測試與 code review 能力，讓 AI 產出的 code 更可控。

## 8. 面試與技能補強清單

### 兩週內優先補

- Swift UIKit 基礎：Auto Layout、UIViewController lifecycle、UITableView/UICollectionView、programmatic UI。
- MVVM / Coordinator / dependency injection 基本說法。
- App Store release / TestFlight / provisioning / Fastlane 基礎。
- Unit Test / UI Test：至少能在一個個人 App 補 3-5 個可展示測試。
- 英文作品集摘要：每個核心專案 120-180 字英文說明。

### 一個月內補

- Swift Concurrency：async/await、Task、MainActor、cancellation。
- Combine 或 RxSwift 擇一，LINE/Gogoro/17LIVE 常會看 reactive experience。
- Objective-C 閱讀能力：不用很深，但要能看懂 existing code 與 Swift bridge。
- CI/CD：GitHub Actions 或 Fastlane 做一個簡單 build/test lane。
- Crash reporting：Firebase Crashlytics 或 Sentry，至少能說如何追 issue。

### 不列入補強主線

- 不走 .NET MAUI 投職，所以不要把時間花在 MAUI 深挖或 C# 企業系統題。
- 不走純 UI/UX 投職，所以不要把時間花在重做大量 Figma 視覺稿。你需要的是把產品判斷放進工程履歷，而不是變成純設計作品集。

履歷健診前輩提醒後，下一份工作除了看職稱，也要看公司與職缺是否能補足你目前較少的 **長期產品迭代經驗**。

- App 是核心產品或核心使用者入口。

- 短期交付、行銷活動頁、WebView 包裝、內部工具。
- 職稱是 App Engineer，但實際上不是核心 App 產品。
- 薪資偏低且成長路線不清楚的遠端職缺。

- 投 Flutter 職缺時，履歷標題應直接改成 **Flutter Engineer** 或 **Mobile Engineer (Flutter)**，這是針對職缺的關鍵字優化。
- 投 App Engineer / Mobile Engineer 職缺時，履歷標題建議用 **Mobile App Engineer (Flutter & iOS/SwiftUI)**，保留多平台能力。
- SwiftUI / iOS 背景不是 Flutter 投遞的弱點，而是護城河；它可以被包裝成 native integration、App Store、Plugin、平台限制與 iOS 使用者體驗的能力。
- 全遠端職缺要特別強調：獨立開發、非同步溝通、文件化、Notion/規格整理、UI/UX 到 Flutter 落地能力。

### 不走的方向

- 不用 .NET MAUI 當投職主線。
- 不投純 UI/UX Designer。
- 不把自己包裝成只會 Figma 或只會 C# 的人。
- 不用「Vibe Coding」當履歷主標籤；對外改說 **AI-assisted development workflow** 或 **Agent-assisted App Development**。

### 三個月內最重要的補強

1. **UIKit / Auto Layout / programmatic UI**
2. **Objective-C 閱讀與 Swift 混編**
3. **Unit Test / UI Test / CI/CD**
4. **AI 產出 code 的 review checklist**
5. **英文技術面試表達**
6. **三個主打專案的 case study：Pickup、FindToilets、Mish**

三個月內不需要變成傳統純手刻工程師，但需要讓面試官相信：即使用 agent 開發，你也能讀懂產出、發現問題、修正問題、寫測試、驗證行為，並維護產品品質。

### 接下來的實際策略
