挑戰與解決 #1：物流 API 的選擇與整合

**情境：**開發初期需要找到一個能夠整合台灣多家物流業者的 API，才能實現「一站式」包裹查詢的核心功能。

**困難點：**一開始嘗試了國外知名的物流追蹤 API（如 AfterShip），但發現這些服務並不以台灣常用的物流業者為主，像是超商取貨（7-11、全家、萊爾富）幾乎都不支援。後來在 GitHub 上尋找開源方案，雖然找到了一些，但普遍存在**穩定性不足、支援的物流業者太少**等問題。

**解決過程：**持續搜尋後發現了 Track.TW，這是一個專門針對台灣物流的追蹤整合網站，且提供開源免費的 API 可以使用。經過測試確認其穩定性與涵蓋範圍後，決定採用其 API 作為核心物流資料來源，成功整合了 21 家台灣物流業者。

**成果：**透過 Track.TW API 成功實現全台主要物流業者的整合查詢，涵蓋超商取貨、宅配、電商物流與國際快遞四大類別，滿足了台灣網購族的一站式查詢需求。

挑戰與解決 #2：伺服器端自動推播架構設計

**情境：**為了讓使用者在不開啟 APP 的情況下也能即時收到包裹狀態更新通知，需要建立一套伺服器端的自動推播系統。

**困難點：**iOS 不允許 APP 在背景長時間執行輪詢任務，因此無法在客戶端定期查詢物流狀態。需要將輪詢邏輯搬到伺服器端，但這涉及**排程任務管理、多用戶包裹批次查詢、狀態變更偵測與推播觸發**等多個環節的協調。

**解決過程：**採用 Firebase Cloud Functions 搭配 Cloud Scheduler 建立每 15 分鐘執行一次的排程任務，批次輪詢所有使用者的包裹狀態。透過 Firestore Trigger 監聽文件變更，當偵測到狀態更新時自動觸發 FCM 推播通知，並設計了多語系通知模板（繁中、簡中、英文）。

**成果：**成功建立完整的伺服器端推播架構，使用者無需開啟 APP 即可即時收到包裹狀態變更、到店提醒與每日取貨提醒等通知，大幅提升使用體驗。
