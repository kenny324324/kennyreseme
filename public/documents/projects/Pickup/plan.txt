設計流程｜Figma

**以需求驅動設計：**沒有使用 Figma 繪製線稿，而是以自身作為目標使用者，從「快速查詢、直覺操作」的角度直接發想介面架構與互動流程。

**邊做邊調整的迭代方式：**設計靈感來自實際使用過程中的體驗反饋，在開發過程中不斷調整 UI 細節，確保每個操作流程都符合直覺。以深色主題為基底，搭配品牌色系營造沉穩的視覺風格。

**功能分層與導航設計：**採用四大分頁架構（包裹、統計、歷史、設定），清楚劃分功能區域，讓使用者能快速找到所需功能。

開發流程｜技術

**技術架構選定：**採用 SwiftUI 搭配 SwiftData 作為客戶端架構，使用 Firebase 生態系（Auth、Firestore、Cloud Functions、FCM、Analytics、Crashlytics）處理後端服務與即時同步。

**物流資料整合：**串接 17track API 作為物流查詢核心，整合多種主流物流業者，涵蓋超商取貨、宅配、電商物流與國際快遞等常見情境。搭配 Carrier 列舉與 CarrierDetector 正則比對實現智慧物流辨識。

**雲端同步架構：**設計 Firestore 雲端與 SwiftData 本地的雙向同步機制，搭配 echo 防迴圈機制確保資料一致性。Apple Sign In 作為唯一登入方式，確保使用者資料安全。

**AI 辨識功能：**透過 Firebase Cloud Functions 建立 Gemini API 代理端點，客戶端將截圖上傳後由伺服器端進行 AI 分析，提取物流單號、業者、取貨資訊等結構化資料。

**自動化推播系統：**使用 Cloud Scheduler 每 15 分鐘觸發 Cloud Functions 批次輪詢所有使用者的包裹狀態，透過 Firestore Trigger 偵測變更並觸發 FCM 推播，支援三語系通知模板。
