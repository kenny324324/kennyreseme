挑戰與解決 #1：Spotify Developer Quota Mode 限制

**情境：**APP 開發完成後準備上架讓更多使用者使用，需要透過 Spotify Developer Platform 取得 API 存取權限。

**困難點：**Spotify 於 2025 年更新開發者政策，將 API 存取分為 Development Mode 與 Extended Quota Mode。Development Mode 僅允許 5 位經開發者手動加入白名單的使用者存取，且開發者本身須維持 Spotify Premium 帳號。若要開放給一般大眾使用，必須申請 Extended Quota Mode，但條件極為嚴苛：申請者須為已註冊的企業組織（不接受個人開發者）、服務需已上線且擁有至少 25 萬月活躍用戶，並需在 Spotify 主要市場運營。這對獨立開發者而言幾乎是不可能達到的門檻。

**解決過程：**評估後決定將 APP 定位為個人使用工具，在 Development Mode 的 5 人限制內運作。同時為了通過 App Store 審核，實作了 Demo Mode 機制——內建模擬資料，讓 Apple 審核人員無需實際登入 Spotify 帳號即可完整體驗 APP 的所有功能，順利通過審核並上架。

**成果：**APP 成功上架 App Store，雖然受限於 Quota Mode 無法大規模開放使用，但作為個人工具已充分滿足需求，同時也展現了面對平台政策限制時的應變能力。

挑戰與解決 #2：自製圖表的動畫與效能平衡

**情境：**為了打造以圖表為核心的差異化體驗，決定不使用第三方圖表套件，全部以 SwiftUI 原生繪圖實作。

**困難點：**自製圖表需要處理大量細節：折線圖的漸進式繪製動畫、多條折線的透明度切換、歌曲跌出排行榜時的虛線斷點處理、Y 軸動態縮放、資料點標籤的防重疊邏輯等。特別是首頁的 Top 5 多軌折線圖，五條折線同時動畫加上互動式選取，容易造成畫面卡頓。

**解決過程：**使用 SwiftUI 的 `trim(from:to:)` 搭配動畫修飾器實現漸進式折線繪製，並透過遮罩技術處理跌出排行榜的虛線區間。針對效能問題，將圖表的重繪觸發條件最小化，僅在資料或選取狀態改變時才重新計算路徑，避免不必要的 View 重建。標籤位置則根據折線方向動態計算偏移量，確保不與趨勢線重疊。

**成果：**實現了流暢的圖表動畫體驗，折線圖的繪製動畫、脈衝特效與互動式選取都能順暢運作，成功打造出與市面上同類型 APP 截然不同的圖表視覺化體驗。
