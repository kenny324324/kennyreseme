設計流程｜Figma

**以自身需求驅動設計：**沒有使用 Figma 繪製設計稿，而是以自己作為目標使用者，直接在 Xcode 中邊開發邊調整介面，從「快速找到廁所」的核心需求出發設計操作流程與視覺呈現。

**適配 iOS 26 設計語言：**開發期間正值 Apple 推出 Liquid Glass 設計語言，因此將 UI 全面適配最新的設計規範，採用毛玻璃質感與現代化視覺風格，讓 APP 在視覺上與最新的 iOS 系統保持一致。

**地圖為核心的介面架構：**以全螢幕地圖作為主介面，搭配底部滑動面板（Bottom Sheet）呈現附近廁所列表與搜尋功能，讓使用者在不離開地圖的情況下即可完成大部分操作。

開發流程｜技術

**資料來源確認：**開發前先調查台灣是否有公廁公開資料，確認環境部提供完整的公廁 API（data.moenv.gov.tw）後，才正式開始規劃與開發。

**三層資料載入架構：**設計 Cache → 內建 JSON → API 的三層載入策略。啟動時優先讀取本地快取（7 天有效期），若無快取則載入內建的 JSON 資料，同時在背景非同步更新 API 資料，兼顧啟動速度與資料即時性。

**地圖與標記系統：**使用 MapKit 建立互動式地圖，實作動態標記聚合機制與 debounce 更新策略，解決大量標記的效能瓶頸。搭配 CoreLocation 進行使用者定位與附近廁所排序。

**社群功能整合：**透過 CloudKit 公開資料庫實作評分與評論系統，搭配 Google Places API 查詢營業時間資訊，豐富廁所的詳細資訊頁面。
